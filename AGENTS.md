# AGENTS.md — Инструкции для AI-агентов

## О проекте
**cli-task-tracker** — консольный интерактивный таск-трекер на Node.js и локальной базе данных SQLite (`better-sqlite3`), разработанный в рамках учебного курса. Проект ориентирован на простоту (KISS/YAGNI), чистоту трёхслойной архитектуры и удобный интерактивный TUI-опыт.

---

## Технологический стек и окружение
- **Среда выполнения:** Node.js LTS (v20+ / v22+)
- **База данных:** `better-sqlite3` (локальный файл `tasks.db` в корне проекта, синхронный драйвер)
- **TUI/Интерфейс:** `@inquirer/prompts` (интерактивные списки, ввод, подтверждения)
- **Стилизация консоли:** встроенный `util.styleText` (без лишних внешних зависимостей)
- **Язык интерфейса и документации:** русский
- **Язык кода, комментариев в кодовой базе и идентификаторов:** английский / русский (согласно текущему коду)

## Архитектура и структура файлов
Проект строго следует **трёхслойной архитектуре (Layered Architecture)**, зафиксированной в Конституции проекта:

```text
d:\AI_course\
├── index.js          # Контроллер / точка входа: связывает ui.js и db.js, цикл навигации
├── db.js             # Слой данных: инициализация SQLite, схема, транзакции, SQL (CRUD, теги, приоритеты)
├── ui.js             # Слой представления: Inquirer промпты, экраны, форматирование текста и цвета
├── tasks.db          # Локальная база данных SQLite (в .gitignore)
├── package.json      # Зависимости и скрипты
├── specs/            # Спецификации фичей (Spec-Kit: 001-cli-task-tracker, 002-task-priorities)
├── tasks/            # PRD проекта (prd-cli-task-tracker.md)
└── .specify/         # Конфигурация Spec-Kit и Конституция (.specify/memory/constitution.md)
```

### Разделение ответственности (Strict Separation of Concerns)
1. **`db.js` — единственный модуль, где разрешён SQL:**
   - Никаких вызовов терминала, `console.log` или промптов.
   - Синхронные вызовы `better-sqlite3`. Операции записи оборачиваются в транзакции (`db.transaction`).
   - Управляет схемой (`tasks`, `tags`, `task_tags`), каскадным удалением и валидацией данных.
2. **`ui.js` — единственный модуль для ввода/вывода в консоль:**
   - Никаких SQL-запросов и прямых обращений к БД.
   - Все экраны, меню, валидаторы пользовательского ввода и цветовое кодирование (`green` — успех, `red` — ошибка/предупреждение, `gray` — теги/метаданные).
3. **`index.js` — координатор потока управления:**
   - Не содержит ни SQL, ни UI-промптов.
   - Главный цикл приложения, обработка навигации («Назад в меню»), корректное завершение (`SIGINT` / Ctrl+C → закрытие соединения с БД и `process.exit(0)`).

## Правила разработки и Конституция проекта

При внесении любых изменений AI-агент **ОБЯЗАН** соблюдать принципы Конституции (`.specify/memory/constitution.md`):

1. **I. Простота прежде всего (Simplicity First / YAGNI):**
   - Никакой преждевременной абстракции или кода «на будущее». Код должен быть понятен junior-разработчику.
   - Не добавлять фичи, которых нет в PRD.
2. **II. Интерактивность вместо флагов (Interactive-First UX):**
   - Навигация стрелками (`↑`/`↓`) и выбор по `Enter`. Пользователь не обязан вводить флаги или запоминать числовые ID.
   - Все пустые состояния (нет задач, нет тегов) обязаны выводить понятное сообщение и возвращать в меню.
   - Некорректный ввод не должен ронять приложение — запрашивать повторный ввод.
3. **III. Локальность и надёжность данных:**
   - `tasks.db` создаётся автоматически.
   - Любые изменения сохраняются в SQLite немедленно.
   - Корректное закрытие БД по выходу или `Ctrl+C`.
4. **IV. Неприкосновенность слоёв:**
   - Запрещено смешивать SQL с UI в одном файле.
5. **Non-Goals (запрещено реализовывать без обновления PRD):**
   - Веб-интерфейс, REST API, сетевые запросы, облачная синхронизация.
   - Авторизация и многопользовательский режим.
   - Дедлайны, таймеры, системные уведомления.
   - Подзадачи (иерархические деревья), экспорт/импорт в JSON/CSV.

## Процесс работы со спецификациями (Spec-Kit)
Проект использует методологию **Spec-Kit**:
- Требования формируются в PRD (`tasks/prd-cli-task-tracker.md`).
- Каждая новая фича описывается в `specs/<номер>-<имя>/`:
  - `spec.md` — функциональные требования и user stories.
  - `plan.md` — технический дизайн и проверка соответствия конституции.
  - `tasks.md` — пошаговый список задач для реализации.
  - `contracts/` — контракты API слоёв (`db-api.md`, `ui.md`).

## Чеклист проверки изменений (Scenario-Based Verification)
Автоматические тесты опциональны, но агент должен убедиться, что:
1. **Запуск:** `node index.js` запускается без ошибок и выводит главное меню.
2. **CRUD-цикл:** создание задачи, просмотр, переключение статуса (выполнена/активна), редактирование названия/тегов/приоритета, удаление.
3. **Персистентность:** перезапуск приложения сохраняет все созданные и изменённые данные.
4. **Устойчивость:** пустой ввод, пробелы, спецсимволы корректно обрабатываются валидаторами `ui.js`.
5. **Границы архитектуры:** новые функции `db.js` не выводят ничего в stdout; функции `ui.js` не импортируют `db.js`.
