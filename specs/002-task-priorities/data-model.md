# Data Model (дельта): Приоритеты задач

**Feature**: 002-task-priorities | **Date**: 2026-11-25

Дельта к базовой модели MVP — [../001-cli-task-tracker/data-model.md](../001-cli-task-tracker/data-model.md).
Таблицы `tags` и `task_tags` не меняются. Решения — [research.md](./research.md) R1–R3, R6.

## tasks — новое поле

| Поле | Тип | Ограничения | Назначение |
|------|-----|-------------|------------|
| `priority` | TEXT | NOT NULL, DEFAULT `'medium'`, CHECK (`priority` IN (`'high'`, `'medium'`, `'low'`)) | Приоритет задачи (FR-101, FR-102, FR-104) |

Значения и ранг для сортировки:

| Значение | Русская метка | Символы | Ранг сортировки |
|----------|---------------|---------|-----------------|
| `high` | Высокий | `!!!` | 0 |
| `medium` | Средний (умолчание) | `!!` | 1 |
| `low` | Низкий | `!` | 2 |

## Миграция существующих баз

Баз, созданных MVP, колонки `priority` не содержат. Миграция выполняется при старте
приложения, если колонка отсутствует (research.md R2):

- проверка наличия колонки через `PRAGMA table_info(tasks)`;
- добавление колонки с `DEFAULT 'medium'` — все существующие задачи получают «средний»
  (FR-108, SC-104);
- повторный запуск не выполняет действий (идемпотентность);
- существующие строки, статусы, теги и связи не изменяются (принцип III).

## Правила валидации

| Правило | Источник | Уровень |
|---------|----------|---------|
| Приоритет только из набора {`high`, `medium`, `low`} | FR-101 | слой db (проверка до записи, ошибка `Недопустимый приоритет`) + CHECK в БД |
| При создании без явного выбора приоритет = `medium` | FR-102, US1-1 | слой db (значение по умолчанию параметра `createTask`) |
| Приоритет не влияет на статус, теги и название | US3-3, R6 | — (независимые атрибуты) |
| Отсутствие приоритета у старых задач трактуется как `medium` | FR-108 | схема (DEFAULT при миграции) |

## Переходы состояний

Переходы статуса из MVP не меняются. Приоритет меняется в любом состоянии задачи
(активна или выполнена) через `updateTask(id, { priority })` и сохраняется немедленно
(FR-014, FR-107):

```text
АКТИВНА/ВЫПОЛНЕНА  --изменить приоритет-->  АКТИВНА/ВЫПОЛНЕНА (другой priority, тот же статус)
```

## Представление списка (обновлено)

Порядок списка всех задач и списка по тегу (FR-006 из 001, FR-106 из 002):

1. `is_completed ASC` — активные выше выполненных;
2. приоритет по рангу (`high` → `medium` → `low`);
3. `created_at DESC`, затем `id DESC` — новые сверху внутри группы.

Фильтр по тегу (FR-007) и список тегов не меняются. Подробности запроса —
[contracts/db-api.md](./contracts/db-api.md).
