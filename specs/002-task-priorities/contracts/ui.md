# Контракт UI (дельта): Приоритеты задач

**Feature**: 002-task-priorities | **Date**: 2026-11-25

Дельта к [контракту UI MVP](../../001-cli-task-tracker/contracts/ui.md). Реализуется в `ui.js`,
оркестрируется `index.js`. Тексты — на русском (конституция). Решения — research.md R4, R5.

## Список всех задач (и список по тегу)

Над списком выводится легенда приоритетов:

```text
=== Все задачи ===

Приоритет: !!! высокий · !! средний · ! низкий

❯ [ ] !!! Сдать отчёт #work #urgent
  [ ] !!  Купить продукты #personal
  [ ] !   Почитать главу 3 #study
  [x] Сделать домашку #study
```

- Активная задача: `[ ]` + метка приоритета + название + теги серым `#имя`.
- Выполненная задача: `[x]` + название (зелёным) + теги; метка приоритета **не выводится**.
- Порядок: активные (высокие → средние → низкие, внутри — новые сверху), затем выполненные
  (FR-106).
- Пустой список и остальные правила отображения — без изменений из MVP.

## Форма добавления задачи (дельта)

Шаги MVP сохраняются; добавляется **последний шаг** — выбор приоритета:

1. Название (input) — без изменений.
2. Теги (checkbox + новые через запятую) — без изменений.
3. **Приоритет** (select), курсор по умолчанию на «Средний»:

```text
? Приоритет:
❯ Средний (!!) — по умолчанию
  Высокий (!!!)
  Низкий (!)
```

- Подтверждение `Enter` без перемещения курсора сохраняет «средний» (US1-1, SC-101).
- После шага приоритета — `✓ Задача добавлена` и возврат в главное меню (без изменений).

## Подменю действий над задачей (дельта)

Пункт «Изменить приоритет» добавляется между «Редактировать» и «Удалить»:

```text
=== Задача: Сдать отчёт ===

❯ Переключить статус (Выполнено/Не выполнено)
  Редактировать
  Изменить приоритет
  Удалить
  ← Назад к списку
```

Подменю выбора приоритета:

```text
? Новый приоритет:
  Высокий (!!!)  (сейчас)
  Средний (!!)
  Низкий (!)
  ← Назад
```

- Текущее значение помечается `(сейчас)`.
- Выбор нового значения → сохранение → `✓ Приоритет обновлён` → возврат в список задач
  (правило FR-010 из 001 с уточнением Clarifications Q1).
- «← Назад» — приоритет не меняется, никаких сообщений.
- Пункт доступен и для выполненных задач (US3-3).

## Общие правила (дельта)

| Правило | Требование |
|---------|-----------|
| Метки приоритета читаются без цвета | Assumptions spec (монохромная деградация) |
| Цветовая палитра не расширяется | FR-013 |
| Метка не выводится для выполненных задач | Edge Cases spec, R4 |
| Ошибок при сохранении приоритета пользователь не видит, кроме внутренних (`Ошибка: ...`) | contracts/ui.md MVP, раздел «Контракт ошибок» |
