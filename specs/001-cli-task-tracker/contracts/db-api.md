# Контракт db.js: Интерактивный CLI Task Tracker (MVP)

**Feature**: 001-cli-task-tracker | **Date**: 2026-11-25

Контракт модуля доступа к данным. `db.js` — единственное место, где допустим SQL
(принцип IV конституции). Все функции синхронные (`better-sqlite3`). Каждая операция
записи выполняется в транзакции — данные фиксируются немедленно (FR-014).

## Инициализация

```js
initDb(dbPath) -> void
```

- Создаёт файл БД (если нет) и таблицы `tasks`, `tags`, `task_tags`
  (см. [data-model.md](../data-model.md)), включает `PRAGMA foreign_keys = ON`.
- Идемпотентно: повторный вызов на существующей базе ничего не ломает.
- Вызывается один раз из `index.js` до главного цикла.

## Операции над задачами

```js
createTask(title, tagNames[]) -> { id }
```
- `title` — непустая строка (пробелы обрезаются; пустое название → `Error`).
- `tagNames` — массив имён; теги создаются при отсутствии (case-insensitive),
  пустые/пробельные имена отбрасываются; дубли в массиве схлопываются.

```js
listTasks() -> TaskView[]
```
- `TaskView = { id, title, is_completed (0|1), created_at, tags: string[] }`
  (теги отсортированы по имени; сортировка списка — активные первыми, затем новые
  сверху; точный ORDER BY фиксируется в tasks-фазе).

```js
listTasksByTag(tagName) -> TaskView[]
```
- Только задачи, связанные с тегом с точным именем (case-insensitive).

```js
getTask(id) -> TaskView | undefined
```

```js
toggleTask(id) -> newIsCompleted (0|1)
```
- Инвертирует статус, возвращает новое значение. Несуществующий `id` → `Error`.

```js
updateTask(id, { title?, tagNames? }) -> void
```
- Обновляет только переданные поля; `title` валидируется как в `createTask`;
  набор тегов заменяется целиком.

```js
deleteTask(id) -> void
```
- Удаляет задачу; связи `task_tags` удаляются каскадно.

## Операции над тегами

```js
listUsedTags() -> { id, name }[]
```
- Только теги, у которых есть хотя бы одна связь с задачей (для меню фильтрации).

## Завершение работы

```js
closeDb() -> void
```
- Закрывает соединение с SQLite; вызывается при «Выход» и по `SIGINT` (FR-012).

## Инварианты контракта

1. Никакой SQL за пределами `db.js` (принцип IV).
2. Никакого вывода в консоль внутри `db.js` — только возврат значений/ошибок.
3. Каждая мутирующая операция атомарна (транзакция), не оставляет частичных изменений.
4. Схема создаётся автоматически; миграций для MVP нет.

Ответственность за отображение (форматы, цвета, тексты) лежит на `ui.js` —
см. [ui.md](./ui.md).
