# Контракт UI: Интерактивный CLI Task Tracker (MVP)

**Feature**: 001-cli-task-tracker | **Date**: 2026-11-25

Контракт пользовательского интерфейса — единственная «внешняя» поверхность
приложения. Реализуется модулем `ui.js`, оркестрируется `index.js`.
Тексты интерфейса — на русском (конституция, Technology Constraints).

## Главное меню (запуск приложения)

Экран запуска показывает меню из 4 пунктов (порядок фиксирован):

```text
=== Task Tracker ===

❯ Просмотреть все задачи
  Фильтровать задачи по тегу
  Добавить новую задачу
  Выход
```

- Навигация: `↑`/`↓`, подтверждение: `Enter`.
- После любого действия (кроме «Выход») управление возвращается сюда (FR-010).
- `Ctrl+C` в любом месте приложения = выход (FR-012).

## Экраны

### 1. Список всех задач

```text
=== Все задачи ===

 [ ] Купить продукты #personal
 [x] Сделать домашку #study
```

- Формат строки: индикатор `[ ]`/`[x]`, название, теги серым `#имя`.
- Выполненные — зелёным (или приглушённым); активные — обычным цветом (FR-013).
- Выбор задачи стрелками → подменю действий; в конце списка — пункт «← Назад в меню».
- Пустой список: `Список задач пуст. Создайте первую задачу!` → возврат в меню (FR-011).

### 2. Фильтр по тегу

- Шаг 1: список существующих тегов (select) + пункт «← Назад в меню».
- Шаг 2: список задач с выбранным тегом (формат как у списка всех задач), затем
  возврат в главное меню.
- Нет тегов: `Теги пока не созданы` → возврат в меню (FR-011).
- У выбранного тега нет задач: `У этого тега пока нет задач` → возврат в меню.

### 3. Добавление задачи

- Шаг 1 (input): `Название задачи:` — пустой/пробельный ввод не принимается,
  выводится `Название не может быть пустым. Попробуйте снова:` и ввод повторяется (FR-002).
- Шаг 2 (multiselect): `Выберите теги (пробел — отметить, Enter — подтвердить):`
  список существующих тегов + опция «➕ Новый тег».
- Шаг 3 (input, только если выбран «Новый тег»): `Новые теги через запятую:`
  например `work, urgent`. Пустой ввод — теги не добавляются.
- Успех: `✓ Задача добавлена` (зелёным) → главное меню.

### 4. Подменю действий над задачей

```text
=== Задача: <название> ===

❯ Переключить статус (Выполнено/Не выполнено)
  Редактировать
  Удалить
  ← Назад к списку
```

- **Переключить статус**: инвертирует `is_completed`, выводит `✓ Статус обновлён`.
- **Редактировать**: подменю «Редактировать название» / «Редактировать теги» /
  «← Назад»; валидация названия — как при добавлении.
- **Удалить** (confirm, красное предупреждение):
  `Удалить задачу «<название>»? (y/N)` — при `y` задача удаляется и выводится
  `✓ Задача удалена`; при `n` — ничего не меняется (FR-009).

## Общие правила отображения

| Правило | Требование |
|---------|-----------|
| Возврат в главное меню после любого действия, кроме «Выход» | FR-010 |
| Зелёный — успех/выполненные, серый — теги, красный — предупреждения удаления | FR-013 |
| Дружелюбные сообщения для всех пустых состояний | FR-011 |
| Экран отделяется заголовком `=== ... ===` (очистка экрана — опционально, PRD §6) | PRD §6 |
| Некорректный ввод никогда не приводит к падению приложения | SC-004 |

## Контракт ошибок

Единственный класс ожидаемых ошибок пользователя — некорректный ввод; он обрабатывается
повтором ввода с сообщением. Внутренние ошибки (недоступность БД) выводятся красным
сообщением вида `Ошибка: <причина>` и приложение корректно завершается (не «падает»
с необработанным стек-трейсом).
