# Data Model: Интерактивный CLI Task Tracker (MVP)

**Feature**: 001-cli-task-tracker | **Date**: 2026-11-25

Модель данных для локального SQLite-хранилища `tasks.db` (см. research.md, D6).
Имена таблиц/полей — контракт модуля `db.js` (см. [contracts/db-api.md](./contracts/db-api.md)).

## Сущности

### tasks

Задача — единица списка дел.

| Поле | Тип | Ограничения | Назначение |
|------|-----|-------------|------------|
| `id` | INTEGER | PRIMARY KEY, AUTOINCREMENT | Уникальный идентификатор (FR-004) |
| `title` | TEXT | NOT NULL | Название задачи; непустое (валидация на уровне UI перед записью) |
| `is_completed` | INTEGER | NOT NULL, DEFAULT 0 | Статус: 0 — активна, 1 — выполнена |
| `created_at` | TEXT | NOT NULL | Дата/время создания (ISO 8601) |

### tags

Тег — именованная категория.

| Поле | Тип | Ограничения | Назначение |
|------|-----|-------------|------------|
| `id` | INTEGER | PRIMARY KEY, AUTOINCREMENT | Уникальный идентификатор |
| `name` | TEXT | NOT NULL, UNIQUE (case-insensitive: `COLLATE NOCASE`) | Имя тега (`work`, `study`, …) |

### task_tags

Связь «задача–тег» — многие-ко-многим.

| Поле | Тип | Ограничения | Назначение |
|------|-----|-------------|------------|
| `task_id` | INTEGER | NOT NULL, FK → tasks(id) ON DELETE CASCADE | Ссылка на задачу |
| `tag_id` | INTEGER | NOT NULL, FK → tags(id) ON DELETE CASCADE | Ссылка на тег |

- PRIMARY KEY (`task_id`, `tag_id`) — исключает дубли связи.
- Записи-сироты невозможны: включён `PRAGMA foreign_keys = ON`.

## Правила валидации (из требований)

| Правило | Источник | Уровень |
|---------|----------|---------|
| Название задачи непустое и не состоит из пробелов | FR-002, US1-2 | UI (повторный ввод) + запись блокируется |
| Тег нормализуется: обрезка пробелов, пустые значения отбрасываются | Edge Cases | UI/слой db (защита в обоих слоях) |
| Тег уникален по имени без учёта регистра | FR-007, Edge Cases | БД (UNIQUE) + повторное использование существующего id |
| Повторный тег у одной задачи не создаёт вторую связь | Edge Cases | БД (PK-составной) |
| Статус — только 0/1 | FR-008 | Слой db (toggle: `1 - is_completed`) |

## Переходы состояний задачи

```text
            создать                    toggle                 toggle
  [нет] ─────────────▶ АКТИВНА (0) ───────────▶ ВЫПОЛНЕНА (1) ───────────▶ АКТИВНА (0)
                          │  edit (title/tags — состояние не меняет)
                          ▼
                        УДАЛЕНА (строка удалена; связи task_tags каскадно;
                        тег без задач перестаёт появляться в списке фильтрации)
```

## Представления/запросы, поддерживающие требования

- **Список всех задач** (FR-006): tasks + агрегированный список тегов через
  LEFT JOIN task_tags/tags, сортировка: сначала активные, затем по `created_at` desc
  (порядок сортировки — решение реализации, зафиксировано в tasks-фазе).
- **Фильтр по тегу** (FR-007): JOIN через task_tags по имени тега.
- **Список доступных тегов** (FR-007): tags, у которых есть хотя бы одна связь
  в task_tags.
- **Удаление задачи** (FR-009): DELETE tasks → каскад по task_tags; теги без связей
  остаются в таблице tags, но не показываются в фильтре (правило выборки выше).

Подробные сигнатуры операций — [contracts/db-api.md](./contracts/db-api.md).
