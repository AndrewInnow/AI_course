# Quickstart: Интерактивный CLI Task Tracker (MVP)

**Feature**: 001-cli-task-tracker | **Date**: 2026-11-25

Руководство по ручной проверке работоспособности. Реализует принцип V конституции:
фича считается готовой, только когда все сценарии пройдены. Соответствует «Метрикам
успеха» PRD и SC-001…SC-006 спецификации.

## Предварительные требования

1. Node.js LTS (20+) установлен: `node --version`.
2. Зависимости установлены: `npm install`.
3. Файл `tasks.db` отсутствует (чистый первый запуск) — либо удалите его для проверки
   сценария инициализации.

## Запуск

```bash
npm start        # или: node index.js
```

Ожидание: появляется главное меню из 4 пунктов; навигация работает стрелками;
ошибок на экране нет (SC-001). Файл `tasks.db` создаётся автоматически (US5-3).

## Сценарий 1: Полный CRUD и фильтрация (SC-002)

1. **Добавление**: «Добавить новую задачу» → название `Купить продукты`, тег `personal`
   (новый) → убедиться, что появилось `✓ Задача добавлена`.
2. Ещё две задачи: `Прочитать главу 3` (тег `study`), `Написать отчёт` (теги `work, urgent`
   через запятую).
3. **Просмотр**: «Просмотреть все задачи» → все 3 задачи видны, у каждой теги серым,
   все как `[ ]`.
4. **Статус**: выбрать задачу → «Переключить статус» → задача стала `[x]` и зелёной.
5. **Редактирование**: выбрать задачу → «Редактировать» → «Редактировать название» →
   новое название отобразилось в списке.
6. **Фильтрация**: «Фильтровать задачи по тегу» → выбрать `work` → показана только
   `Написать отчёт`.
7. **Удаление**: выбрать задачу → «Удалить» → подтвердить `y` → задача исчезла;
   повторить с ответом `n` → задача осталась.

## Сценарий 2: Сохранность данных (SC-003)

1. Завершить работу пунктом «Выход» — приложение закрывается без ошибок.
2. Запустить снова — все задачи, статусы (`[ ]`/`[x]`) и теги на месте.
3. Прервать работу `Ctrl+C` во время работы с меню — корректное завершение,
   при следующем запуске данные целы.

## Сценарий 3: Устойчивость к некорректному вводу (SC-004)

1. «Добавить новую задачу» → нажать Enter на пустом названии → сообщение об ошибке,
   ввод запрашивается повторно; ввести `   ` (только пробелы) → тот же результат.
2. Ввести название из 200+ символов → задача сохраняется целиком, вывод не «ломается».
3. В фильтре: убедиться, что тег без задач после удаления последних связанных задач
   больше не предлагается (либо выводится пояснение).

## Сценарий 4: Пустые состояния (FR-011)

1. На чистой базе: «Просмотреть все задачи» → «Список задач пуст. Создайте первую
   задачу!» и возврат в меню.
2. «Фильтровать задачи по тегу» без единого тега → «Теги пока не созданы» и возврат
   в меню.

## Критерий завершённости

Все 4 сценария пройдены полностью — фича соответствует метрикам успеха PRD.
Любое расхождение фиксируется как дефект с указанием шага сценария.
